# viSparkle — ショップの購入時の応援 設計書

- 作成日: 2026-11-03
- ステータス: 承認済み（2026-11-03、節ごとにユーザーが承認。書面の最終レビューはユーザーが実施）
- 前提: ショップ（物のグッズ、`2026-11-02-shop-goods-design.md`）とデジタル作品（`2026-11-03-digital-goods-design.md`）の注文・決済の仕組み

## 1. 目的

グッズやデジタル作品を買うファンが、**買い物のついでに任意の金額を上乗せして**クリエイターを応援できるようにする。価格をファンが自由に決める方式（Pay What You Want）ではなく、商品の価格はそのままで、注文に応援額を足す。

### 決まっていること（ユーザーの回答）

- 応援額は定額ボタンと自由入力で選ぶ。既定は「なし」
- 応援分には商品とは**別の手数料率**をかける（設定値）
- クリエイターはショップ設定で応援の受付をオン・オフできる（既定はオン）
- 応援は注文1件（＝クリエイター1人）につき1つ。購入前の確認画面で選ぶ
- 取り消しと返金は、応援分も含めて全額返金する（応援だけの一部返金はしない）
- 応援のひとことメッセージは今回の範囲外
- 作り方は「注文に応援の列を足し、同じ Checkout に明細行を1行足す」（応援を注文明細の1行にする案、応援を別の決済にする案は採らない）

## 2. 成功基準

1. 応援を受け付けているクリエイターの確認画面で応援額を選ぶと、合計に応援額が加わり、その金額で Stripe Checkout が作られる。Checkout の明細に「クリエイターへの応援」が表示される
2. 運営の手数料は、商品と送料には通常の率、応援には応援の率をかけた額の合計になる。どちらの率も注文を作った時点の値を保存し、あとで設定が変わっても注文の金額と売上の計算は変わらない
3. 応援の受付がオフのクリエイターには、確認画面に応援の欄が出ず、応援額を付けた購入手続きはエラーになる
4. 取り消し・返金では、応援分も含めて全額が返金され、送金と手数料も取り戻される
5. 購入者の注文詳細、クリエイターの注文詳細、管理画面、注文確定メールで、応援額が内訳として表示される
6. クリエイターの売上ページで、応援の件数・金額と、手数料を引いた額が分かる
7. 応援額を選ばない（0 円の）注文は、今までとまったく同じに動く

## 3. 範囲外

応援のひとことメッセージ、クリエイターが定額ボタンの金額を変えること、応援だけの一部返金、支援プラン（サブスク）への上乗せ、商品なしで応援だけを送ること。

## 4. データモデル

### creators（変更）

| カラム          | 型                 | 備考                                             |
| --------------- | ------------------ | ------------------------------------------------ |
| accepts_support | bool, default true | 購入時の応援を受け付けるか。ショップ設定で変える |

### orders（変更）

| カラム              | 型                      | 備考                               |
| ------------------- | ----------------------- | ---------------------------------- |
| support_amount      | unsigned int, default 0 | 応援額（円・税込）。0 なら応援なし |
| support_fee_percent | unsigned int, default 0 | 注文を作った時点の応援分の手数料率 |

- `total` は「`subtotal` ＋ `shipping_fee` ＋ `support_amount`」にする。既存の注文は `support_amount` が 0 なので値は変わらない
- 既存の `fee_percent` は商品と送料にかける率として使い続ける

### 設定（`config/fanbox.php` の `billing`）

| キー                   | 既定                               | 備考                                           |
| ---------------------- | ---------------------------------- | ---------------------------------------------- |
| support_fee_percent    | 5（`BILLING_SUPPORT_FEE_PERCENT`） | 応援分の手数料率                               |
| support_amount_min     | 100                                | 応援額の下限（円）                             |
| support_amount_max     | 50000                              | 応援額の上限（円）                             |
| support_amount_presets | `[100, 300, 500, 1000, 3000]`      | 確認画面の定額ボタン。すべて下限〜上限に収める |

## 5. 購入と決済の流れ

既存の流れ（`2026-11-02-shop-goods-design.md` の 6.2）に次を足す。変えるのは `App\Services\Shop\OrderCheckout` と、確認画面からのリクエストだけ。

### 5.1 購入手続きの開始（`POST /cart/{creator}/checkout`）

- リクエストに `support_amount`（任意、既定 0）を足す。0、または `support_amount_min`〜`support_amount_max` の整数でなければバリデーションエラー
- クリエイターの `accepts_support` が false で、`support_amount` が 0 でなければバリデーションエラー（確認画面を開いたあとにクリエイターがオフにした場合も含む。確認画面に戻して「このクリエイターは現在応援を受け付けていません」と表示する）
- 注文を作るときに `support_amount` と、`support_fee_percent`（その時点の設定値）を保存する。`total` に応援額を含める
- 同じ購入者×同じクリエイターの `pending` を置き換えるときは、新しい注文に今回選んだ応援額を保存する（前の応援額は引き継がない）

### 5.2 Checkout セッション

- `support_amount` が 0 より大きいとき、明細の最後に `LineItem('クリエイターへの応援', support_amount, 1)` を足す（送料の行のあと）
- `application_fee_amount` を次で計算する（どちらも切り捨て）

    ```
    intdiv((subtotal + shipping_fee) × fee_percent, 100) + intdiv(support_amount × support_fee_percent, 100)
    ```

    今の `intdiv($order->total * $order->fee_percent, 100)` を置き換える。計算は `Order` のメソッド（例: `platformFeeAmount()`）にまとめ、Checkout と売上の集計の両方から使う

- Stripe に送るそれ以外のパラメータ、冪等キー、メタデータは変えない

### 5.3 Webhook・照合ジョブ・返金

変えない。Checkout の金額に応援が含まれるので、支払い完了・期限切れ・返金の処理はそのまま応援分も扱う。返金は今と同じ全額（`reverse_transfer=true`、`refund_application_fee=true`）なので、応援分の送金と手数料も取り戻される。

`FakeGateway` も変えなくてよい（明細と手数料は `PaymentCheckoutRequest` で渡される）。偽の決済画面には明細がそのまま表示される。

## 6. 画面

### 購入前の確認画面（`/cart/{creator}/confirm`、`resources/js/pages/fan/cart-confirm.tsx`）

- クリエイターの `accepts_support` が true のときだけ「クリエイターを応援する（任意）」の欄を出す
    - 「なし」と定額ボタン（`support_amount_presets`）、「金額を入力」（数値入力。下限〜上限）。既定は「なし」
    - 欄の下に注記: 「応援額は全額返金の場合を除き返金されません。応援によって特典は付きません」（最終的な文言は運営が決める）
- 金額の内訳を「商品小計・送料（物があるときだけ）・応援（0 円なら出さない）・合計」にする。応援額を変えると合計がその場で変わる
- 「支払いへ進む」で `support_amount` を送る。バリデーションエラーは欄の下に出す

### ショップ設定（`/creator/shop`、`resources/js/pages/creator/shop.tsx`）

- 「購入時の応援を受け付ける」のスイッチを足す。説明文に応援分の手数料率を表示する
- オフにしても、作成済みの注文（`pending` を含む）は変わらない

### 注文の表示

- 購入者の注文詳細（`/orders/{order}`）、クリエイターの注文詳細（`/creator/orders/{order}`）、管理画面の支払いで、金額の内訳に「応援」の行を出す（0 円なら出さない）
- クリエイターの注文一覧で、応援付きの注文に印（例: 「応援あり」のバッジ）を付ける
- 注文確定メール（購入者・クリエイター）の内訳に「応援」の行を足す。取り消し・返金のメールは返金額（合計）をそのまま出す

### 売上（`/creator/earnings`、`resources/js/pages/creator/earnings.tsx` の「ショップの売上」）

- 期間ごとに「うち応援」の件数（応援付きの注文数）と金額を足す
- 「手数料を引いた額」は 5.2 の `platformFeeAmount()` を使い、注文ごとに保存した2つの率で計算する
- 返金済みの注文の扱いは今と同じ（応援分も返金に含まれる）

### 特定商取引法のページ（`resources/js/pages/legal/tokushoho.tsx`）

「商品代金以外の必要料金」に書き足す。下書き（最終的な文言は運営が決める）:

- 購入時に、任意でクリエイターへの応援額を追加できます。追加した金額は購入前の確認画面に表示し、商品代金と一緒にお支払いいただきます

**要確認（運営）**: 運営が販売者となる今の決済の構成（destination charge、`on_behalf_of` なし）では、応援額も運営の売上の一部として扱われる可能性が高い。消費税の扱いと特定商取引法上の表記は、公開前に運営（税理士）が確認する。実装はこの確認を待たずに進めてよいが、本番での公開はこの確認のあとにする。

## 7. エラー時の扱い

| 状況                                                 | 扱い                                                                                   |
| ---------------------------------------------------- | -------------------------------------------------------------------------------------- |
| 確認画面を開いたあとにクリエイターが受付をオフにした | 購入手続きの開始でバリデーションエラー。確認画面に戻して知らせる（応援なしなら進める） |
| 範囲外の金額・整数でない値                           | バリデーションエラー                                                                   |
| 手続きの途中で応援の手数料率の設定が変わった         | 注文に保存した率のまま進む                                                             |
| クリエイターの取り消し・運営の返金                   | 応援分も含めて全額返金（5.3）                                                          |

## 8. テスト

既存と同じく Pest と、本番と同じ MySQL（`testing` データベース）を使う。

- **購入手続きの開始**: 応援額と `support_fee_percent` が注文に保存され `total` に含まれること、範囲外・整数でない値のエラー、受付オフのクリエイターへの応援のエラー（応援なしなら進めること）、`pending` を置き換えたときに新しい応援額になること
- **手数料の計算**: `platformFeeAmount()` の計算（商品と応援で別の率、それぞれの切り捨て、応援 0 円のとき今と同じ値になること）
- **StripeGateway**: 応援の明細行が送られること、0 円のときは送られないこと、`application_fee_amount` の値
- **返金**: 応援付きの注文で全額が返金されること
- **売上の集計**: 応援の件数・金額と、手数料を引いた額
- **ショップ設定**: 受付のオン・オフを保存できること、他人の設定を変えられないこと
- **表示**: 注文詳細と注文確定メールに応援の行が出ること（0 円なら出ないこと）
- `types:check` と `pint` を通す

## 9. 運用

- `.env.example` に `BILLING_SUPPORT_FEE_PERCENT` を足す
- Stripe の Webhook のイベントは増えない
- デモデータ（`--seed`）の注文の一部に応援額を付ける
