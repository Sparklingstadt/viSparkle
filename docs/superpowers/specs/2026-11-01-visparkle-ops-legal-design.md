# viSparkle — サブプロジェクト3「運営・法対応」設計書

- 作成日: 2026-11-01
- ステータス: 承認済み（ユーザーが仕様・提案を事前承認。最終レビューはユーザーが実施）
- 前提: サブプロジェクト1（コア）と2（決済）が main にマージ済み。本番は Laravel Cloud（Stripe はテストモード）

## 1. 目的

本番のキーで一般のユーザーから課金を始めるために、法令上必要な表示・同意と、運営に必要な最低限の機能をそろえる。

- 特定商取引法に基づく表記、利用規約、プライバシーポリシーを掲示し、会員登録時に同意を得る
- 有料の支援を申し込む直前に、特商法の「最終確認画面」に必要な事項を表示する
- 会員が自分で退会できる（課金中の支援は自動で解約）
- 運営が通報を受け付け、投稿の非公開化・会員の利用停止・返金を行える管理画面を持つ

## 2. 成功基準

1. フッターから特商法表記・利用規約・プライバシーポリシーをいつでも開ける。特商法表記の事業者情報は環境変数から表示し、未設定なら本番の課金を止める
2. 会員登録は規約とプライバシーポリシーへの同意が必須。同意した版と日時を記録する。規約の版が上がると、次のアクセス時に再同意を求める
3. 「このプランで支援する」の後に申込内容の確認画面を挟み、金額・支払い時期・契約期間（毎月自動更新）・解約方法・返金の扱いを表示してから Stripe に進む
4. ファンは自分で退会できる。課金中の支援は退会時に即時解約される（返金なし。確認画面で明示）
5. クリエイターは「活動終了」で新規受付を止め、支援者全員を期間末で解約できる。有効な支援が無くなれば退会できる
6. 会員は投稿・クリエイターを通報できる。運営は管理画面で通報を処理し、投稿の非公開化、会員の利用停止を行える
7. 運営は管理画面から支払いを返金できる（送金と運営手数料も戻す）。Stripe ダッシュボードで行った返金も記録に反映され、売上から差し引かれる
8. 利用停止されたクリエイターの支援者は即時解約され、直近の支払いが全額返金される

## 3. 方式

| 項目                 | 採用                                                    | 理由                                                                                  |
| -------------------- | ------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| 規約・ポリシーの本文 | リポジトリ内の Markdown（`resources/legal/*.md`）を表示 | 版管理が git で済む。改定は PR でレビューできる。管理画面での編集は YAGNI             |
| 事業者情報           | 環境変数 → `config/legal.php`                           | 個人情報をリポジトリに入れない。環境ごとに変えられる                                  |
| 管理画面             | 既存の Inertia + React で `/admin` を自作               | 必要な画面が少なく、Filament 等の導入より軽い。認可は既存のミドルウェアの形に合わせる |
| 管理者               | `users.is_admin`（Artisan コマンドで付与）              | 管理者は運営の数人。ロール管理は YAGNI                                                |

## 4. 法的表示

### 4.1 ページ

| URL                | 内容                     |
| ------------------ | ------------------------ |
| `/legal/tokushoho` | 特定商取引法に基づく表記 |
| `/legal/terms`     | 利用規約                 |
| `/legal/privacy`   | プライバシーポリシー     |

- 全ページ共通のフッター（公開レイアウトとアプリのレイアウトの両方）に3つのリンクを置く
- 本文は `resources/legal/terms.md`、`resources/legal/privacy.md` を Markdown として描画する（`league/commonmark`、HTML 入力は無効化）。各ファイルの先頭に版（`version: 2026-11-01`）を持つ frontmatter を置く
- 規約とポリシーの文面は運営者向けの**ひな形**として作成し、ページ冒頭のコメントと手順書に「公開前に専門家の確認を受けること」と明記する

### 4.2 特商法表記の項目（`config/legal.php`）

| 項目           | 環境変数                   | 備考                                                                                       |
| -------------- | -------------------------- | ------------------------------------------------------------------------------------------ |
| 販売事業者     | `LEGAL_SELLER_NAME`        | 必須                                                                                       |
| 運営統括責任者 | `LEGAL_RESPONSIBLE_PERSON` | 必須                                                                                       |
| 所在地         | `LEGAL_ADDRESS`            | 個人事業主は「請求があれば遅滞なく開示します」とできる（`LEGAL_DISCLOSE_ON_REQUEST=true`） |
| 電話番号       | `LEGAL_PHONE`              | 同上                                                                                       |
| メールアドレス | `LEGAL_EMAIL`              | 必須                                                                                       |

固定の文言（ビューに記述）: 販売価格（各プランのページに税込で表示）、商品代金以外の必要料金（なし。通信料はお客様負担）、支払方法（クレジットカード等、Stripe による決済）、支払時期（申込時に初回、以後毎月同日に自動更新）、提供時期（決済完了後すぐ）、解約（「支援中」からいつでも停止でき、次回支払日の前日まで閲覧可）、返品・返金（デジタルコンテンツの性質上、原則として返金しない。運営が必要と認めた場合を除く）、動作環境。

`config('legal.ready')` は必須項目がすべて埋まっているときだけ true。**`APP_ENV=production` かつ Stripe の本番キー（`sk_live_`）で `legal.ready` が false のとき、支援の開始（Checkout）を拒否する**（422「現在お申し込みを受け付けていません。」とエラーログ）。テストキーでは拒否しない。

### 4.3 同意の記録

- `users` に `terms_version`（string, nullable）、`terms_accepted_at`（datetime, nullable）を追加
- 会員登録フォームに「利用規約とプライバシーポリシーに同意する」チェックボックス（必須。リンクは別タブ）。`CreateNewUser` で検証し、現行の版と日時を保存する
- 現行の版は `config('legal.terms_version')`（= `resources/legal/terms.md` の frontmatter の版。キャッシュして読む）
- ミドルウェア `EnsureTermsAccepted`（ログイン済みの web ルートすべて。除外: ログアウト、法的ページ、再同意ページ、Webhook）: 版が異なれば `/legal/accept` へリダイレクト。そこで新しい規約へのリンクと同意ボタン（POST で記録）
- 既存ユーザー（版が null）も初回アクセス時に同意を求める

### 4.4 申込内容の確認画面（特商法の最終確認画面）

`GET /@{slug}/plans/{plan}/confirm`（ログイン・メール認証必須）。プランのボタン「このプランで支援する」はこの画面へ遷移する。表示:

- クリエイター名、プラン名、**金額（税込）/ 月**
- 支払い時期: 「本日お支払い。以後、毎月◯日に自動で更新されます」
- 契約期間: 「解約するまで毎月自動更新」
- 解約方法: 「『支援中』ページからいつでも停止できます。停止後も次回のお支払い日まで閲覧できます。」
- 返金: 「デジタルコンテンツのため、お支払い後の返金は原則としてお受けしていません。」
- 特商法表記・利用規約へのリンク
- ボタン「お支払いへ進む（Stripe）」→ 既存の `POST /@{slug}/plans/{plan}/support`

検証（自分自身、受付停止、口座未登録、既に支援中）は確認画面の表示時にも行い、問題があればクリエイターページに戻してトースト。プラン変更（既存の支援者）は確認画面を経ない（既存のダイアログに金額差の説明があるため）。

## 5. 退会

### 5.1 ファン

設定 → アカウントの「アカウントを削除」（既存）を次のように変える。

- 確認ダイアログに、課金中の支援（クリエイター名・金額）を一覧し「削除すると、これらの支援は直ちに解約されます。今月分の返金はありません」と表示
- 削除の処理（`AccountDeletion` サービス）:
    1. 課金中（`status=active` かつ `stripe_subscription_id` あり）の支援を Stripe で即時解約（`cancelSubscriptionNow`）。失敗したら削除を中止し、エラーを表示（課金が残る削除はしない）
    2. ユーザーを削除（既存の cascade。`payments.user_id` は null になり、売上の記録は残る）
- 既存の「課金中の支援があると削除できない」検証（ファン側）は、この処理に置き換える

### 5.2 クリエイター

- クリエイター設定に「活動を終了する」を追加（確認ダイアログ）。処理（`CreatorClosure` サービス）:
    1. `creators.closed_at` を記録し、全プランを受付停止
    2. 課金中の支援すべてを期間末で解約（`setCancelAtPeriodEnd(true)` → `SubscriptionSync::apply`）。失敗した支援はログに残して続行し、結果の件数をトーストで表示
- 活動終了したクリエイター: クリエイターページに「このクリエイターは活動を終了しました」。トップの一覧から外す。新規支援は不可（既存の支援者は期間末まで閲覧可）。再開は「活動を再開する」（`closed_at` を null に。プランの受付は各自で再開）
- アカウント削除の検証: クリエイターに **有効な支援（`status=active`）が1件でもあれば** 削除不可「有効な支援者がいるため削除できません。『活動を終了する』で支援を停止し、期間の終了をお待ちください」。停止予約中も含める（支援者の閲覧期間を守るため）

## 6. 通報

- `reports` テーブル: `id`, `reporter_id`（FK users, nullOnDelete）, `target_type`（`post` / `creator`）, `target_id`, `reason`（`inappropriate` 不適切な内容 / `rights` 権利侵害 / `adult` 成人向け / `spam` スパム / `other` その他）, `body`（text, 最大1000字, nullable）, `status`（`open` / `resolved` / `dismissed`）, `resolved_by`（FK users, nullable）, `resolved_at`, `resolution_note`（nullable）, timestamps
- 投稿ページとクリエイターページに「通報する」（ログイン必須。モーダルで理由と詳細）。`POST /reports`、10回/時/ユーザー。同じ会員が同じ対象を未処理のまま重複通報しても1件にまとめる（既存の open を更新）
- トースト「通報を受け付けました。ご協力ありがとうございます。」

## 7. 管理画面 `/admin`

- `users.is_admin`（bool, default false）。Artisan `fanbox:admin {email} {--revoke}` で付与・剥奪
- ミドルウェア `admin`: 管理者以外は 404。すべての管理操作は `admin_actions` に記録（`admin_id`, `action`, `target_type`, `target_id`, `note`, timestamps）
- サイドバーに管理者だけ「管理」を表示

| 画面                  | 機能                                                                                                       |
| --------------------- | ---------------------------------------------------------------------------------------------------------- |
| `/admin`              | 未処理の通報数、直近30日の売上・返金の合計、有効な支援数                                                   |
| `/admin/reports`      | 通報一覧（未処理を先頭）。対象へのリンク。「対応済み」「却下」（メモ付き）。対象への操作（下記）へのボタン |
| `/admin/posts/{post}` | 投稿の非公開化／解除（理由必須）。`posts.hidden_at`, `posts.hidden_reason`                                 |
| `/admin/users`        | 検索（メール・名前・slug）。利用停止／解除（理由必須）。`users.suspended_at`, `users.suspended_reason`     |
| `/admin/payments`     | 支払い一覧（新しい順、クリエイター・支援者で絞り込み）。「返金」                                           |

### 7.1 投稿の非公開化

- `hidden_at` が入った投稿は、作者以外には存在しないものとして扱う（404、一覧から除外、`Entitlement` も false）。作者には投稿管理と投稿ページに「運営により非公開になっています（理由）」
- 作者は編集できるが、公開状態にしても `hidden_at` は外れない

### 7.2 会員の利用停止

- `suspended_at` が入った会員はログインできない（Fortify の認証で「このアカウントは利用停止中です。」）。ログイン中のセッションも次のリクエストでログアウトさせる（ミドルウェア）
- 停止された会員がクリエイターの場合: クリエイターページと投稿は 404。**支援者全員を即時解約し、各支援の直近の支払いを全額返金する**（`CreatorSuspension` サービス。失敗はログと管理画面に件数表示）。解除しても解約・返金は戻らない（再開は「活動を再開する」と同じ扱い）
- 停止された会員がファンの場合: 課金中の支援を即時解約（返金なし）

### 7.3 返金

- ゲートウェイに `refundInvoice(string $invoiceId, string $reason): RefundData` を追加。Stripe ではその請求の PaymentIntent に対し、`reverse_transfer=true`（クリエイターへの送金を戻す）、`refund_application_fee=true`（運営手数料も戻す）で全額返金する。部分返金は YAGNI
- `payments` に `refunded_amount`（unsigned int, default 0）、`refunded_at`（nullable）を追加
- Webhook `charge.refunded`（プラットフォーム）を追加購読。請求に紐づく支払いの `refunded_amount` を Stripe の値で更新（ダッシュボードからの返金も反映）
- 返金した支払いの支援はそのまま（解約は別操作）。管理画面の返金ダイアログで「支援も解約する」を選べる（即時解約）
- 収益画面の集計は `amount - refunded_amount` を売上とする。手数料の目安も返金後の額で計算
- 返金・解約の結果はトーストと `admin_actions` に残す

### 7.4 チャージバック

- Webhook `charge.dispute.created`（プラットフォーム）を購読し、`payments.disputed_at` を記録。管理画面の支払い一覧に「異議申し立て」バッジ。対応（証拠の提出）は Stripe ダッシュボードで行う（手順書に記載）

## 8. データモデル（追加・変更のまとめ）

| テーブル      | 追加                                                                                                                                                                 |
| ------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| users         | `is_admin` bool default false, `suspended_at` datetime null, `suspended_reason` string(500) null, `terms_version` string(32) null, `terms_accepted_at` datetime null |
| creators      | `closed_at` datetime null                                                                                                                                            |
| posts         | `hidden_at` datetime null, `hidden_reason` string(500) null                                                                                                          |
| payments      | `refunded_amount` unsigned int default 0, `refunded_at` datetime null, `disputed_at` datetime null                                                                   |
| reports       | 新規（§6）                                                                                                                                                           |
| admin_actions | 新規（§7）                                                                                                                                                           |

`is_admin`・`suspended_*`・`hidden_*`・`closed_at`・返金系は `#[Fillable]` に入れない（強制代入のみ）。

## 9. エラー処理

- Stripe の失敗（`BillingException`）: 退会は中止してエラー表示。活動終了・利用停止・返金は、成功・失敗の件数をトーストで返し、失敗をログ（`billing.ops_failed`）と `admin_actions` に残す。再実行できる（冪等: 解約済み・返金済みはスキップ）
- 返金済みの支払いを再度返金しようとした場合は 422

## 10. テスト方針

- 法的ページの表示、`legal.ready` が false の本番＋本番キーで Checkout が 422、テストキーでは通る
- 登録時の同意必須・記録、版が上がると再同意へリダイレクト、除外ルート
- 確認画面の表示項目、検証エラー時の戻り
- 退会: 課金中の支援が即時解約されてから削除、Stripe 失敗で中止
- 活動終了: 全プラン受付停止、支援が期間末解約、トップから除外、再開
- 通報: 作成・重複統合・レート制限
- 管理: 非管理者は 404、非公開化で作者以外 404・一覧除外、利用停止でログイン不可・セッション切断、クリエイター停止で即時解約＋返金、返金で `refunded_amount` 更新と収益の差し引き、`charge.refunded` と `charge.dispute.created` の Webhook
- `StripeGateway::refundInvoice` のリクエスト内容（reverse_transfer, refund_application_fee）

## 11. スコープ外

- 規約・ポリシーの文面の法的な最終確認（運営者が専門家に依頼する）
- 部分返金、返金の承認フロー、複数管理者の権限の区別
- 通報の自動判定、NG ワード、画像の自動検査
- 退会後のデータ保持期間の自動削除（プライバシーポリシーで方針のみ記載）
- 特商法表記以外の法令表示（資金決済法の前払式支払手段等は、ポイント等を扱わないため対象外）
- メール通知（サブプロジェクト4）
