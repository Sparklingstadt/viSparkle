# viSparkle — ショップ（デジタル作品）設計書

- 作成日: 2026-11-03
- ステータス: 承認済み（2026-11-03、節ごとにユーザーが承認。書面の最終レビューはユーザーが実施）
- 前提: ショップ（物のグッズ、`2026-11-02-shop-goods-design.md`、#35）が main にマージ済み

## 1. 目的

candy-rain-stores の統合の2段階目。1段階目のショップ（カート・注文・Stripe Checkout の destination charge・Webhook の同期・返金）の上に、**ファイルとダウンロードの権限**を足し、クリエイターがグッズと並べてデジタル作品（画像集・PDF・音声・ZIP など）を売れるようにする。

この設計書のとおりに作り終えたら、candy-rain-stores のリポジトリをアーカイブする。

### 決まっていること（ユーザーの回答）

- 物のグッズとデジタル作品は、同じカート・同じ注文で一緒に買える。物が1つでもあれば送料とお届け先を求め、デジタルだけなら求めない
- デジタル作品は在庫を持たず、1人1点（数量は常に1）。購入済みの作品はカートに入れられない
- 1作品に複数のファイル（最大10）を付けられる。1ファイル 100MB まで（投稿の添付ファイルと同じ上限・同じアップロードの仕組み）
- ダウンロードの回数と期限は制限しない（乱用対策はレート制限だけ）
- 返金されたらダウンロードできなくなる。チャージバック（`disputed_at`）が起きた注文も同じ
- デジタル作品を含む注文はクリエイターが取り消せない。返金できるのは運営だけ
- 購入者がダウンロードできるのは**作品が公開中のあいだだけ**。作品の削除・非公開、運営による非公開、クリエイターの活動終了・停止で、購入者もダウンロードできなくなる
- 特定商取引法のページに足す項目は 7.3 の下書きのとおり

## 2. 成功基準

1. 口座の登録が済んだクリエイターが、ファイルを1件以上付けたデジタル作品を公開すると、ショップのタブと商品ページに「デジタル」の印付きで表示される
2. ファンがデジタル作品だけをカートに入れて支払うと、送料 0、お届け先の入力なしで注文が `paid` になり、注文の詳細からファイルをダウンロードできる
3. 物とデジタルを一緒に買うと、送料とお届け先が求められ、1つの注文になる。発送の操作は物について今までどおり行える
4. 購入済みの作品はもう一度カートに入れられない。2つのタブから同時に購入しても、同じ作品を含む支払い済みの注文は1件にしかならない
5. ダウンロードは毎回権限を確かめる。他人の注文、支払い待ち、返金済み、チャージバック、作品が公開中でない、クリエイターが活動中でない、購入者が停止中のいずれかなら 404 になる
6. デジタル作品を含む注文は、クリエイターの画面に「取り消して返金」が出ず、サーバーでも弾かれる。運営は返金でき、返金すると物の明細だけ在庫が戻る
7. 偽の決済ドライバで一連の流れを動かせる

## 3. 範囲外

ダウンロードの回数・期限の制限、ダウンロードの記録、購入時点のファイルの保存（版の管理）、透かし・DRM、100MB を超えるファイル（ブラウザから直接ストレージへアップロードする仕組み）、購入済み作品をまとめて見る「ライブラリ」の画面、デジタル作品の数量限定販売、一部返金でのダウンロード停止。

## 4. 方式

`products` に種類（`kind`）を足し、デジタル作品のファイルを `product_files` に置く。**ダウンロードの権限は保存せず、注文から都度計算する**（「その作品を含む、自分の `paid` か `shipped` の注文がある」）。権限を別のテーブルに持たないので、返金・Webhook・支払い後の取り消しなどのどの経路でも、注文の状態と権限がずれない。1段階目の `Orders` / `OrderSync` / `OrderCheckout` は、在庫と送料の扱いに種類の分岐を足すだけで使える。

採らなかった案: 購入権のテーブルを別に持つ案（すべての状態遷移で更新が要り、ずれやすい）、デジタル作品を別のモデルにする案（カート・注文・画面・通報・管理画面が二重になり、「一緒に買える」と合わない）。

## 5. データモデル

### products（変更）

| カラム | 型                             | 備考                                                                       |
| ------ | ------------------------------ | -------------------------------------------------------------------------- |
| kind   | string(16), default `physical` | `ProductKind` enum（`physical` / `digital`）。作成時に決め、あとで変えない |

- デジタル作品では `stock` を使わない（0 のまま。「売り切れ」の判定は物だけ）
- デジタル作品を公開するには `product_files` が1件以上必要。公開中は最後の1件を消せない
- `Product` に `isDigital()`、`isPurchasable()`（物: `isListed()` かつ `stock > 0`、デジタル: `isListed()` かつファイルが1件以上）を足す

### product_files（新規）

| カラム        | 型                   | 備考                                                          |
| ------------- | -------------------- | ------------------------------------------------------------- |
| id            | bigint               |                                                               |
| product_id    | FK products, cascade |                                                               |
| path          | string               | `private` ディスクの `creators/{c}/products/{p}/{ulid}.{ext}` |
| original_name | string(255)          | ダウンロード時のファイル名                                    |
| mime          | string(255)          |                                                               |
| size          | unsigned bigint      | バイト                                                        |
| sort_order    | unsigned int         |                                                               |
| timestamps    |                      |                                                               |

インデックス: `(product_id, sort_order)`。1作品につき最大 10 件（`config('fanbox.product_files_max')`）。種類は問わない。1件 `config('fanbox.attachment_max_kb')`（100MB）まで。

### order_items（変更）

| カラム       | 型                             | 備考                                                                   |
| ------------ | ------------------------------ | ---------------------------------------------------------------------- |
| product_kind | string(16), default `physical` | 購入時のコピー。作品が消えても明細の表示と在庫・送料の判断が変わらない |

### orders（変更なし）

- `shipping_fee` は、物の明細が1つ以上あれば `creators.shipping_fee`、デジタルだけなら 0
- `Order` に `hasPhysical()`、`hasDigital()`（明細の `product_kind` から）を足す

## 6. 購入・決済・ダウンロードの流れ

### 6.1 カート（`Cart`）

- デジタル作品の数量は常に 1。`add` は数量に関わらず 1 にし、すでにカートにあればそのまま。`setQuantity` で 1 以外にはできない
- 次のときはカートに入れられない（`cart` のエラー）
    - 購入済み（「その作品を含む自分の `paid` か `shipped` の注文」がある）→「購入済みの作品です」
    - ファイルが0件 →「現在購入できません」
- `group` の `purchasable` の判定に、デジタルの「ファイルが1件以上」「購入済みでない」を足す。デジタルだけのまとまりは `shipping_fee = 0`

### 6.2 購入手続きの開始（`Orders::reserve` と `OrderCheckout::begin`）

- `reserve` は明細ごとに種類で分ける
    - 物: 今までどおり条件付きで在庫を減らす
    - デジタル: 在庫は触らない。同じトランザクションの中で、作品が公開中・このクリエイターのもの・ファイルが1件以上・購入者が購入済みでないことを確かめる。満たさなければ `cart` のエラーで何も確保しない
- 明細に `product_kind` をコピーし、送料は物の明細があるときだけ足す
- `PaymentCheckoutRequest` に `collectShipping`（bool）を足す。`StripeGateway` は `true` のときだけ `shipping_address_collection` と `phone_number_collection` を送る。`OrderCheckout` は `$order->hasPhysical()` を渡す
- 2つのタブから同時に購入する場合: 今の「購入者×クリエイターで同時に1件」のロックと `pending` の置き換えで、同じ作品を含む `pending` は1件になる。別のクリエイターの作品が同じ注文に入ることはないので、これで足りる

### 6.3 状態

`OrderStatus` は変えない。

- デジタルだけの注文は `paid` が最後の状態。発送の操作は出さず、画面の表示は「購入済み」
- 物を含む注文（混在を含む）は今までどおり「発送済みにする」で `shipped`
- あとで支払う方法の支払い待ち（`pending`）のあいだはダウンロードできない
- 支払い完了のメール（購入者）に「注文の画面からダウンロードできます」と注文へのリンクを足す（デジタルを含む注文のとき）

### 6.4 取り消しと返金（`Orders::refund`）

- `$by === OrderCancelReason::Creator` で、注文にデジタルの明細が1つでもあれば弾く（`order` のエラー「デジタル作品を含む注文は取り消せません。」）。クリエイターの注文の画面にもボタンを出さない
- 運営の返金、ダッシュボードからの全額返金（`charge.refunded`）、取り消し後の支払い完了による自動返金は今までどおり
- 在庫を戻す `restoreStock` は物の明細（`product_kind = physical`）だけを対象にする
- 一部返金（`refunded_amount < total`）ではダウンロードは止めない。全額返金で `refunded` になると止まる

### 6.5 ダウンロード

購入者: `GET /orders/{order}/files/{file}`（`throttle:30,1`）。新しい `ProductFileAccess`（仮称）が次をすべて確かめ、満たさなければ 404、満たせば 5 分の署名付きURL（`Content-Disposition: attachment; filename*=UTF-8''{original_name}`）へ転送する。アプリはファイルの中身を中継しない（`PostFileDownloadController` と同じ方式）。

1. 注文が自分のもので、状態が `paid` か `shipped`、`disputed_at` が null
2. ファイルの作品（`product_id`）がその注文の明細にあり、明細の `product_kind` が `digital`
3. 作品が公開中（`is_published`、`hidden_at` と `deleted_at` が null）
4. クリエイターが活動中（`closed_at` が null、クリエイターのユーザーが停止されていない）
5. 購入者が停止されていない

- 署名付きURLは `PostFileUrls` と同じく `config('fanbox.signed_url_minutes')` 分。署名の処理は `PostFileUrls` から共通の小さなクラス（`PrivateFileUrls`、仮称）に切り出して両方から使う
- 注文の詳細には、デジタルの明細ごとにファイルの一覧（名前・大きさ・「ダウンロード」）を出す。ダウンロードできない状態なら一覧の代わりに理由を出す（「支払いの確認後にダウンロードできます」「返金済みのためダウンロードできません」「この作品は現在公開されていないため、ダウンロードできません」など）。判定は 6.5 と同じ `ProductFileAccess` を使う
- クリエイター: `GET /creator/products/{product}/files/{file}` で自分の作品のファイルをいつでもダウンロードできる（公開中かどうかは問わない）
- クリエイターがファイルを差し替え・追加・削除すると、購入者には今あるファイルがそのまま見える（購入時のファイルは保存しない）

### 6.6 ファイルの保存と削除

- 保存は `PostFileStorer::storeAttachment` と同じ処理を使う。拡張子の正規化とストリームでの書き込みを `PrivateFileWriter`（仮称）に切り出し、`PostFileStorer` と新しい `ProductFileStorer` の両方から使う
- ファイルの削除は行とストレージの両方を消す（`PostFileStorer::delete` と同じ）
- 作品の論理削除ではファイルを消さない（復元のため。購入者もダウンロードできなくなる）
- `PruneOrphanFiles` の `private` ディスクの照合に `product_files.path` を足す（商品画像は `public` ディスクなので別）

## 7. 画面

### 7.1 クリエイター

| URL                                | 変更                                                                                                                                                                                 |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `/creator/products/create`         | 最初に「グッズ」「デジタル作品」を選ぶ。デジタルでは在庫の欄を出さない                                                                                                               |
| `/creator/products/{product}/edit` | デジタルではファイルの欄（アップロード、並べ替え、削除、名前と大きさ、ダウンロード）。ファイルが0件なら「公開するにはファイルを1件以上アップロードしてください」と出し、公開できない |
| `/creator/products`                | 一覧に種類の印。デジタルは在庫の代わりにファイル数                                                                                                                                   |
| `/creator/orders/{order}`          | デジタルだけの注文は「発送済みにする」「取り消して返金」を出さない。混在の注文は「発送済みにする」だけ。明細に種類の印                                                               |

ファイルのルート（`routes/creator.php`）: `POST /creator/products/{product}/files`（`throttle:30,1`）、`PUT /creator/products/{product}/files`（並べ替え。商品画像と同じ形）、`DELETE /creator/products/{product}/files/{file}`、`GET /creator/products/{product}/files/{file}`。Policy は商品と同じ（自分の作品だけ）。

### 7.2 購入者・誰でも見られる画面

| URL                          | 変更                                                                                                                                                                       |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/@{creator}`（ショップ）    | デジタル作品に「デジタル」の印。売り切れの印は物だけ                                                                                                                       |
| `/@{creator}/shop/{product}` | デジタルでは在庫と送料の代わりに「ダウンロード販売」、ファイルの数と合計の大きさ、各ファイルの種類（拡張子）。数量の欄なし。購入済みなら「購入済み」と注文へのリンク       |
| `/cart`                      | デジタルは数量の欄なし。デジタルだけのまとまりは送料 0                                                                                                                     |
| `/cart/{creator}/confirm`    | デジタルを含むとき「デジタル作品は購入後に取り消せません」「作品が非公開になるとダウンロードできなくなるため、早めに保存してください」。物がなければお届けの案内を出さない |
| `/orders/{order}`            | デジタルの明細ごとにファイルの一覧とダウンロード（6.5）。デジタルだけの注文はお届け先の欄を出さない                                                                        |
| `/orders`                    | デジタルだけで `paid` の注文の表示は「購入済み」                                                                                                                           |

### 7.3 特定商取引法のページ

`legal/tokushoho` にデジタル作品の販売の項目を足す。下書き（最終的な文言は運営が決める）:

- **販売価格**: 各作品ページに表示する価格（税込）
- **商品代金以外の必要料金**: ダウンロードにかかる通信料（送料はかからない）
- **引き渡し時期**: 支払いの確認後、すぐに注文の画面からダウンロードできる
- **返品・キャンセル**: 性質上、購入後のキャンセル・返金は受け付けない。ファイルが壊れている・開けない場合は運営に連絡する
- **動作環境**: 各作品ページにファイルの種類と大きさを表示する
- **ダウンロードできる期間**: 作品が公開されているあいだ。作品が非公開になるとダウンロードできなくなるため、購入後は早めに保存する

### 7.4 運営

- 管理画面の注文の一覧・詳細に明細の種類を出す。返金は今までどおり
- 通報・非公開（`hidden_at`）は今までどおり。デジタル作品を非公開にすると購入者もダウンロードできなくなる

## 8. エラー時の扱い

| 状況                                               | 扱い                                                                                                |
| -------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| ファイルのアップロードの失敗                       | 書いたファイルを消してエラーを出す（投稿ファイルと同じ）                                            |
| 11件目のファイル                                   | バリデーションで弾く                                                                                |
| 公開中の作品の最後のファイルを消す                 | 弾く（「公開中の作品からすべてのファイルを消すことはできません。」）                                |
| 作品の論理削除・非公開・運営の非公開               | 購入者もダウンロード不可（404。注文の詳細では理由を表示）。ファイルは残す                           |
| クリエイターの活動終了・停止                       | 同上                                                                                                |
| 購入済みの作品をもう一度カートへ                   | `Cart::add` で弾く。カートに残っていた場合は `group` で購入できないまとまりにし、`reserve` でも弾く |
| 購入手続きの途中でファイルが0件になった            | `reserve` で弾く。Checkout 後は注文の金額のまま進む（ダウンロードは今あるファイル）                 |
| 種類の変更                                         | 編集のリクエストで `kind` を受け取らない                                                            |
| デジタルを含む注文をクリエイターが取り消そうとした | `Orders::refund` で弾く                                                                             |

## 9. テスト

既存と同じく Pest と MySQL（`testing` データベース）。

- **商品**: デジタルの作成（在庫を受け取らない）、種類を変えられないこと、ファイルの追加・上限10件・100MB・並べ替え・削除、0件で公開できないこと、公開中に最後の1件を消せないこと、他人の作品のファイルを触れないこと、クリエイターのダウンロード
- **カート**: 数量1固定、購入済みを弾く、ファイル0件を弾く、デジタルだけのまとまりは送料 0
- **購入手続きの開始**: デジタルだけで送料 0・`collectShipping=false`・在庫が変わらないこと、混在で送料あり・`collectShipping=true`、購入済みを `reserve` で弾くこと、明細に `product_kind` がコピーされること
- **返金**: デジタルを含む注文をクリエイターが取り消せないこと、運営の返金で物の明細だけ在庫が戻ること、`charge.refunded` の全額返金でダウンロードが止まること
- **ダウンロード**: 6.5 の各条件で 404、満たせば署名付きURLへ転送（`Content-Disposition` 付き）、他人の注文のファイル・別の作品のファイルは 404
- **StripeGateway**: `collectShipping=false` のとき `shipping_address_collection` と `phone_number_collection` を送らないこと
- **PruneOrphanFiles**: `product_files` のファイルを消さず、孤立したものだけ消すこと
- `types:check` と `pint`

## 10. 運用

- デモデータ（`--seed`）に、デモクリエイターのデジタル作品を1件（小さなファイル付き）足す
- Stripe の Webhook に足すイベントはない
- 作り終えたら candy-rain-stores のリポジトリをアーカイブする（ユーザーが GitHub で行う）
