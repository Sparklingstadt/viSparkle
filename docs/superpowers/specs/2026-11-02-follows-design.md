# viSparkle — クリエイターのフォロー 設計書

- 作成日: 2026-11-02
- ステータス: 承認済み（2026-11-02）
- 前提: コア・決済・運営・いいね・新着クリエイターの絞り込み（#30）が main にマージ済み

## 1. 目的

支援する前の段階でも、気になるクリエイターの無料の全体公開投稿をフィードで追えるようにする。支援をやめたあとも、無料投稿でつながりを保てるようにする。

## 2. 成功基準

1. ログイン・メール認証済みの会員は、クリエイターページの「フォロー」ボタンでフォローを付け外しできる（1会員1クリエイターにつき1つ）
2. フィードの「すべて」タブに、支援中のクリエイターの全投稿と、フォロー中のクリエイターの無料の全体公開投稿（`required_price = 0`）が新しい順に出る。フォローだけのクリエイターの有料投稿は出ない
3. フィードの「支援中」タブは、これまでのフィードと同じ（支援中のクリエイターの投稿だけ）
4. 支援を始めると自動でフォローが付き、支援をやめてもフォローは残る。フォローはいつでも外せる
5. フォロワー数はクリエイター本人だけが管理画面（支援者ページ）で見られる。誰がフォローしているかは誰にも見せない
6. 退会した会員のフォローは消える

## 3. 方式

| 項目                   | 採用                                                          | 理由                                                                                              |
| ---------------------- | ------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| 記録                   | 新テーブル `follows`（`user_id` × `creator_id` で一意）       | 支援（Stripe の購読と1対1）とは切り離す。0円の `Support` として扱うと課金の処理すべてに分岐が入る |
| フォロワー数           | 列に非正規化しない。表示のたびに `COUNT`                      | 数を見せるのはクリエイター本人の支援者ページだけで、一覧で投稿ごとに数える場面がない              |
| 付け外しの API         | `POST` で付ける / `DELETE` で外す（どちらも冪等）             | いいねと同じ。二重クリックや再送で状態が反転しない                                                |
| 画面の更新             | Inertia の `router.post/delete`（`preserveScroll`）で楽観的に | いいねボタンと同じ作り。失敗したら元に戻してトースト                                              |
| 支援との関係           | 支援を始めたときに自動でフォローを付ける                      | 支援をやめた瞬間に無料投稿までフィードから消えないようにする（§11 で確定）                        |
| フィードの分け方       | 「すべて」「支援中」の2タブ（クエリ `tab`）                   | 自動フォローがあるため「フォロー中だけ」のタブは「すべて」とほぼ重なる（§11 で確定）              |
| フォロワー数の公開範囲 | クリエイター本人だけ。公開ページの props にも含めない         | いいね数の公開範囲を絞った方針に合わせる（§11 で確定）                                            |

## 4. データ

### 4.1 `follows`

| カラム       | 型                     | 備考                                        |
| ------------ | ---------------------- | ------------------------------------------- |
| `id`         | bigint                 |                                             |
| `user_id`    | foreignId → `users`    | `cascadeOnDelete`（退会でフォローも消える） |
| `creator_id` | foreignId → `creators` | `cascadeOnDelete`                           |
| `created_at` | timestamp              | `updated_at` は持たない                     |

- 一意制約: `(user_id, creator_id)`（フィードで会員のフォロー先を引くときにも使う）
- インデックス: `(creator_id)`（フォロワー数を数える。外部キーのインデックスで足りる）

### 4.2 モデル

- `App\Models\Follow`（`UPDATED_AT = null`。`PostLike` と同じ形）
- `User::follows(): HasMany`、`Creator::follows(): HasMany`
- `Creator::follow(User $user): void` / `Creator::unfollow(User $user): void`
    - `follow` は `insertOrIgnore`、`unfollow` は `delete`。どちらも冪等
- `Creator::isFollowedBy(?User $user): bool`

### 4.3 既存の支援者

マイグレーションで、いま有効な支援（`supports.status = active`）を持つ会員に、そのクリエイターのフォローを付ける（`insertOrIgnore` 相当の `INSERT ... SELECT`）。付けないと、既存の支援者だけ「支援をやめたら無料投稿も消える」状態になり、§2.4 と食い違う。`down` ではテーブルごと消すので戻し処理は要らない。

## 5. 誰がフォローできるか

| 条件                       | 付ける                      | 外す | 理由                                           |
| -------------------------- | --------------------------- | ---- | ---------------------------------------------- |
| 未ログイン                 | ×（ボタンでログイン画面へ） | ×    | いいねボタンと同じ                             |
| メール未認証               | ×（認証画面へ）             | ×    | 既存の `verified` ミドルウェアに合わせる       |
| クリエイター本人           | ×（403。ボタンも出さない）  | —    | 自分自身はフォローできない                     |
| 活動を終了したクリエイター | ×（403。ボタンも出さない）  | ○    | 新しい投稿はもう出ない。フォロー中の人は外せる |
| 利用停止中のクリエイター   | ×（404）                    | ×    | クリエイターページ自体が 404（既存）           |
| 上記以外の会員             | ○                           | ○    |                                                |

判定は `App\Http\Controllers\Fan\FollowController` 内で行う（`Entitlement` は投稿の閲覧権限の判定なので、そこには入れない）。

### 5.1 支援で自動フォロー

- `SubscriptionSync::write` が**新しい支援**（`Support` の行を新しく作る場合）を有効（`active`）で保存したとき、`$creator->follow($user)` を呼ぶ。`write` は `DB::transaction` の中で動くので、支援の保存とフォローは一緒に確定する。重複（`duplicate`）や不整合（`mismatch`）で保存しなかったときは付けない
- 既存の支援の更新（プラン変更・停止予約・再開・更新）では付けない。フォローを外した支援者に、勝手に付け直さないため
- 支援が終わってもフォローは外さない
- 新しい支援はチェックアウト完了（Webhook と完了ページ）から `SubscriptionSync` で作られる。偽の決済ドライバ（`fake`）でも同じ経路なので、ローカルでも同じ動きになる

## 6. ルート

`routes/fan.php` の `auth` + `verified` グループに追加する。

| メソッド | URL                  | 名前                      | 応答                                 |
| -------- | -------------------- | ------------------------- | ------------------------------------ |
| POST     | `/@{creator}/follow` | `creators.follow.store`   | `back()`（既に付いていても成功扱い） |
| DELETE   | `/@{creator}/follow` | `creators.follow.destroy` | `back()`（付いていなくても成功扱い） |

- レート制限: `throttle:60,1,creator-follows`
- コントローラーは `App\Http\Controllers\Fan\FollowController`（`store` / `destroy`）

## 7. 表示

### 7.1 クリエイターページ（`public/creator.tsx`）

- props に `viewerFollows: boolean` を足す（未ログインは `false`）
- ヘッダーの下、通報ボタンの左に「フォロー」/「フォロー中」ボタン（新規コンポーネント `components/follow-button.tsx`）
    - フォロー前は「フォロー」（塗り）、フォロー中は「フォロー中」（枠線）
    - 本人のページでは出さない。活動を終了したクリエイターでは、フォロー中の人にだけ「フォロー中」を出し、外せるようにする
    - 未ログインで押すとログイン画面へ（`like-button.tsx` と同じ）
- 押した瞬間に表示を切り替え、失敗したら戻して「フォローできませんでした。」「フォローを外せませんでした。」をトーストで出す

### 7.2 フィード（`fan/feed.tsx`）

- `GET /feed?tab=all|supporting`。不正な値・未指定は `all`
- 「すべて」: 次のどちらかに当たる投稿
    - 支援中のクリエイターの投稿（有料・無料とも。ロック表示は既存どおり）
    - フォロー中のクリエイターの `required_price = 0` の投稿
- 「支援中」: これまでのフィードと同じ条件
- どちらのタブも、公開済み・非公開化されていない・利用停止中でないクリエイターの投稿に限る（既存と同じ）。並びは公開日時の新しい順、1ページ20件
- ページ送りのリンクに `tab` を引き継ぐ（`withQueryString()`）
- タブの見た目と切り替えは、ホームの「新着／人気」タブと同じ作り（`only` で `posts` と `tab` だけ読み直す）
- 見出しの説明: 「支援中・フォロー中のクリエイターの新着投稿」
- 空のとき: 「すべて」は「まだ投稿がありません。」＋「クリエイターを探す」リンク（既存）。「支援中」は「支援中のクリエイターの投稿はまだありません。」

### 7.3 クリエイター管理画面の支援者ページ（`creator/supporters.tsx`）

- props に `followerCount: number` を足し、見出しの下に「フォロワー N人」と出す
- フォロワーは支援者を含む（自動フォローのため）。説明文で「支援者を含みます」と添える

## 8. エラー処理

- 付け外しの失敗（429・500 など）は、画面で表示を元に戻してトーストを出す。サーバー側で特別な処理はしない
- 自分自身・活動終了のクリエイターへの `POST` は 403。画面からは送られない（ボタンを出さない）ので、直接叩かれたときだけ起きる

## 9. テスト方針

- `tests/Feature/Fan/FollowTest.php`
    - 付ける・外すがどちらも冪等であること（2回送っても行が1つ／0）
    - 本人・活動終了のクリエイターへのフォローは 403。活動終了でもフォロー中なら外せる
    - 未ログインはログインへ、未認証は認証画面へリダイレクト
    - クリエイターページの `viewerFollows` が状態どおりになること
- `tests/Feature/Fan/FeedTest.php`（既存に追加）
    - 「すべて」に、フォロー中のクリエイターの無料投稿が出て、有料投稿は出ないこと
    - 支援中のクリエイターは、フォローしていなくても全投稿が出ること
    - 「支援中」タブはフォローだけのクリエイターの投稿を出さないこと
    - 不正な `tab` は `all` 扱い。ページ送りで `tab` が残ること
- 自動フォロー（`tests/Feature/Billing/SubscriptionSyncTest.php` に追加）
    - 新しい支援が有効になるとフォローが付くこと
    - フォローを外したあと、プラン変更や更新では付け直さないこと
    - 支援が終わってもフォローが残ること
- マイグレーション: 既存の有効な支援者にフォローが付き、終了した支援には付かないこと
- 支援者ページの `followerCount` が本人にだけ渡ること。公開ページの props にフォロワー数が含まれないこと
- 退会でフォローが消えること

## 10. スコープ外

- フォロー中のクリエイター一覧のページ
- フォローされたとき・フォロー先が投稿したときの通知
- フォロワーの一覧（クリエイターにも見せない）
- 公開ページでのフォロワー数の表示
- ホームや人気順へのフォロー数の反映

## 11. 検討で確定した事項（2026-11-02）

1. **支援を始めると自動でフォローが付き、支援をやめてもフォローは残る。**（§5.1）
2. **フォロワー数はクリエイター本人だけが見られる。**（§3、§7.3）
3. **フィードは「すべて」「支援中」の2タブ。**（§7.2）
