# viSparkle — 投稿へのいいね 設計書

- 作成日: 2026-11-02
- ステータス: レビュー待ち（§11 の未決事項をユーザーが確認してから実装計画に進む）
- 前提: コア・決済・運営（サブプロジェクト1〜3）が main にマージ済み

## 1. 目的

ファンが投稿に気軽に反応を返せるようにし、クリエイターがどの投稿が喜ばれたかを知れるようにする。

## 2. 成功基準

1. ログイン・メール認証済みの会員は、閲覧できる投稿に「いいね」を付け外しできる（1会員1投稿につき1つ）
2. 投稿ページと投稿カードに、いいね数を表示する（未ログインでも見える）
3. 自分が付けたいいねは、ボタンの状態（塗りつぶし）で分かる
4. クリエイターは自分の投稿一覧（クリエイター管理画面）で各投稿のいいね数を見られる
5. 退会した会員のいいねは消え、数からも差し引かれる

## 3. 方式

| 項目           | 採用                                                    | 理由                                                                                         |
| -------------- | ------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| 記録           | 新テーブル `post_likes`（`user_id` × `post_id` で一意） | 付け外しの判定と退会時の削除に、誰が付けたかが要る                                           |
| 数             | `posts.like_count` に非正規化して保持                   | 一覧（ホーム・クリエイターページ・フィード）で投稿ごとに COUNT しない。`view_count` と同じ形 |
| 付け外しの API | `POST` で付ける / `DELETE` で外す（どちらも冪等）       | トグル1本より、二重クリックや再送で状態が反転しない                                          |
| 画面の更新     | Inertia の `router.post/delete`（`preserveScroll`）で楽観的に更新 | 既存の画面遷移の作りに合わせる。失敗したら元に戻してトースト                         |
| いいねした人の一覧 | 作らない                                            | 支援者が誰かを他の会員に見せないため。クリエイター向けにも初版では YAGNI                     |

## 4. データ

### 4.1 `post_likes`

| カラム       | 型                       | 備考                                         |
| ------------ | ------------------------ | -------------------------------------------- |
| `id`         | bigint                   |                                              |
| `post_id`    | foreignId → `posts`      | `cascadeOnDelete`                            |
| `user_id`    | foreignId → `users`      | `cascadeOnDelete`（退会でいいねも消える）    |
| `created_at` | timestamp                | `updated_at` は持たない                      |

- 一意制約: `(post_id, user_id)`
- インデックス: `(user_id, created_at)`（将来「いいねした投稿」一覧を作るとき用。初版の画面では使わない）

### 4.2 `posts.like_count`

- `unsignedInteger('like_count')->default(0)`
- 付ける・外すときに、`post_likes` の行の追加・削除と同じトランザクションで `increment` / `decrement` する。Eloquent を通さず `toBase()` で更新し、`updated_at` を動かさない（`recordView` と同じ）
- 行が実際に増減したときだけ数を動かす（`insertOrIgnore` の戻り値 / `delete` の件数で判定）。これで冪等になり、数がずれない

### 4.3 退会時の整合

会員の削除は `post_likes` を DB の cascade で消すため、`like_count` が減らない。退会処理（既存の `AccountDeletion`）の中で、削除の前に

```php
Post::whereIn('id', $user->likes()->select('post_id'))->toBase()->decrement('like_count');
```

を実行してから会員を削除する。念のため Artisan コマンド `posts:recount-likes` を用意し、`post_likes` から数え直せるようにする（運用で手動実行。スケジュールはしない）。

## 5. 誰がいいねできるか

| 条件                                   | 付ける | 外す | 理由                                                               |
| -------------------------------------- | ------ | ---- | ------------------------------------------------------------------ |
| 未ログイン                             | ×（ログインへ誘導） | × |                                                                   |
| メール未認証                           | ×（403）| ×   | 既存の `verified` ミドルウェアに合わせる                           |
| 利用停止中の会員                       | —      | —    | ログインできない（既存）                                           |
| 投稿の作者本人                         | ×（403）| —   | 自分の投稿の数を自分で増やせないようにする                         |
| 閲覧権限のない会員（ロックされた投稿） | ×（403）| ○   | 中身を見ていない投稿への評価は意味が薄い。§11-1 で確認したい       |
| 支援をやめた会員（以前は閲覧できた）   | ×      | ○    | 付けたいいねは残る。外すことはいつでもできる                       |
| 非公開化（`hidden_at`）された投稿      | ×（404）| ×（404）| 作者以外には存在しない扱い（既存の投稿ページと同じ）          |
| 下書き・未公開の投稿                   | ×（404）| ×（404）|                                                               |

判定は既存の `Entitlement`（`canView` / `isAuthorOf`）を使い、`PostLikePolicy` にまとめる。

## 6. ルート

`routes/fan.php` の `auth` + `verified` グループに追加する。

| メソッド | URL                              | 名前                | 応答                                      |
| -------- | -------------------------------- | ------------------- | ----------------------------------------- |
| POST     | `/@{creator}/posts/{post}/like`  | `posts.like.store`  | `back()`（既に付いていても成功扱い）      |
| DELETE   | `/@{creator}/posts/{post}/like`  | `posts.like.destroy`| `back()`（付いていなくても成功扱い）      |

- `{post}` が `{creator}` の投稿でなければ 404（`PostPageController` と同じ確認）
- レート制限: `throttle:60,1,post-likes`（連打は UI 側でも抑えるが、サーバーでも上限を置く）
- コントローラーは `App\Http\Controllers\Fan\PostLikeController`（`store` / `destroy`）

## 7. 表示

### 7.1 投稿の props

`PostPresenter::summary()` に次を足す（`detail()` は summary を含むので自動で入る）。

- `like_count: number`
- `liked: boolean` — 閲覧者が付けているか。未ログインなら false
- `can_like: boolean` — §5 の「付ける」が可能か（ボタンを押せる状態にするか）

一覧で `liked` を投稿ごとに問い合わせないよう、コントローラーで閲覧者のいいね済み `post_id` を1回のクエリで取り（`whereIn` で表示中の投稿に限定）、Presenter に渡す。

### 7.2 投稿ページ（`public/post.tsx`）

- 本文の下（添付ファイルの下、通報リンクの上）に、ハートのボタンと数を置く（Lucide の `Heart`。付いていれば塗りつぶし）
- 未ログインで押すとログイン画面へ（ログイン後に投稿ページへ戻る）
- `can_like` が false で `liked` も false のとき（ロック中・作者本人）はボタンを無効にし、数だけ見せる。ロック中なら「支援すると、いいねできます」をツールチップで出す
- 押したら即座に表示を切り替え、失敗したら元に戻して「いいねできませんでした」をトースト

### 7.3 投稿カード（`components/post-card.tsx`）

- サムネイルの下のメタ情報の並びに、ハートのアイコンと数を表示するだけ（押せない）。0 件のときは出さない

### 7.4 クリエイター管理画面の投稿一覧

- 各行にいいね数の列を足す

## 8. エラー処理

- 権限がない（§5 の ×）: 403。画面ではボタンを出さないので、通常は直接リクエストしたときだけ
- 一意制約の競合（同時に2回付ける）: `insertOrIgnore` で吸収し、成功扱い
- レート制限超過: 429。画面はトーストで「時間をおいてお試しください」

## 9. テスト方針

- 付ける: 行が1つでき、`like_count` が 1 増える。2回目は行も数も変わらない
- 外す: 行が消え、数が 1 減る。付いていない状態で外しても数は変わらない（0 未満にならない）
- 付けても `posts.updated_at` が変わらない
- 権限: 未ログインはログインへリダイレクト、未認証 403、作者本人 403、ロック中 403（外すのは可）、非公開化・下書き 404、別クリエイターの URL で 404
- 退会で行が消え、`like_count` が減る
- `posts:recount-likes` で数が `post_likes` の件数に戻る
- props: 投稿ページ・ホーム・クリエイターページ・フィードで `like_count` / `liked` / `can_like` が正しい。一覧でクエリ数が投稿数に比例しない
- フロント: ボタンの楽観的更新と、失敗時の巻き戻し（既存のフロントのテストの範囲で）

## 10. スコープ外

- いいねの通知（クリエイターへのメール・アプリ内通知）
- 「いいねした投稿」一覧ページ
- いいねした人の一覧の表示
- ホームの「人気順」へのいいね数の反映（閲覧数による人気順と合わせて別途検討）
- いいね以外のリアクション（絵文字など）・コメント

## 11. 未決事項（レビューで確認したいこと）

1. **ロック中の投稿にいいねできるか。** 本設計は「閲覧できる投稿だけ」とした。プレビュー（タイトル・カバー）だけで応援の気持ちを示したい場合は、ログイン会員なら誰でも付けられるようにする案もある
2. **いいね数を誰に見せるか。** 本設計は全員に表示とした。クリエイター本人だけに見せる案もある（数が少ない投稿が目立つのを避けたい場合）
3. **クリエイター向けにいいねした人の一覧を出すか。** 本設計は出さない
